# 研报详情页局部图谱

研报页的 `/graph/<slug>` 现在从本篇元数据构建局部网络，使用与 Agent 相同的 `entity-registry.json` 核验别名；无需先进入旧页面链接索引。原有引用、支持、反驳等显式关系继续保留。

- 默认两层：本篇 → 已确认实体／原始标签 ← 相关材料；一层只显示本篇对象和直接明确关系。
- 实体使用稳定 entity_id；同名多义条目不任意指定实体，仍可用原始标签查看共同提及。共同提及不推断为因果或支持关系。
- `local`、`研报`、`pdf` 等通用导入标签不参与发现，避免连接整个库。
- 仅有导入标签的研报显示本篇节点及待补齐研究元数据的提示。此修改不启动重新分析文章的任务，也不改写原文。
- 图谱右侧展示节点详情、关联依据、关系筛选和关联材料列表。实体或标签可跳转其范围，其他材料可设为新中心。

## 性能边界

仅读取并缓存 YAML 头部，复用全库元数据目录；倒排索引按已变化的材料对象或实体字典版本失效。查询只扩展中心的实体和标签，不进行正文或全库节点渲染。

每次最多选择 32 个实体／标签，加入 50 份共同提及的材料，并保留最多 50 个明确关系邻居。总节点仍遵守请求 limit（默认 150、最大 400），总边最多 1,000。优先匹配已确认实体，相关材料按共同对象数量和对象区分度排序；同分时优先较新元数据。

前端使用 Canvas，节点维持统一尺寸；实体菱形、标签方形、材料圆形。提及／标签连线使用虚线；明确关系使用箭头。

## 验证

`tests/page-graph.test.mjs` 覆盖别名跨语言连接、无旧索引页面、一层／两层切换、关系筛选、歧义保留、孤立中心，以及两万份材料时节点／边／返回大小上限。`tests/graph.test.mjs` 验证实际路由读取元数据、编辑后缓存失效和大正文不进入查询路径。
